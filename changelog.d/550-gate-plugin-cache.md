### Changed

- The gate's sessions load the latest shipmill release instead of the installed plugin: each tick that would launch reads the latest version from the marketplace, checks PyPI serves it, and materializes it once into `~/.cache/shipmill/plugin/<version>/` (`$XDG_CACHE_HOME` moves it), shared by every gate on the host. `claude -p` and `claude --bg` start with `--plugin-dir` on that folder, and their `--settings` turns `shipmill@shipmill` off beside the App's `env`; the hooks' self-test runs that folder's hooks. While PyPI doesn't serve the latest yet, sessions load the newest cached version (`plugin: <latest> waits for PyPI; sessions load <cached>`); a failed step with nothing cached is `PLUGIN_FAILED`, naming the step, its error, and its fix, and starts no session. The gate no longer pauses on a stale install (`PLUGIN_STALE`), since no session loads it, and refuses `--claude-arg` `--plugin-dir` and `--plugin-url`, as spec 031 sets out (#550)
