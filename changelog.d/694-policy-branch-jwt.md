### Fixed

- The landing checks compare against the branch releases land on: the `branch` that `.github/shipmill.toml` sets, and origin/HEAD only when the config sets none. In a repo whose GitHub default branch was an older, diverged branch, `shipmill worktrees` read every merged worktree as not landed, so the gate's prune removed none, and `shipmill status` read the repo as stuck, with the fix `fetch origin master:master`. Now `shipmill worktrees` and its prune, the gate's `--refresh`, `shipmill milestones`, the repo line of `shipmill status`, and the github-ship-watch skill's fetch, plan, and reads at `origin/<branch>` all follow the config's branch. `shipmill doctor` WARNs when GitHub's default branch isn't the config's branch, with the fix `gh api -X PATCH repos/<repo> -f default_branch=<branch>` (#694)
- The gate's App check and the App's bot login sign their JWT when they run, not with the tick's start time. A tick whose prune ran past the JWT's 9 minutes no longer ends in `GitHub refused the JWT ... 401`, which read like a wrong key (#694)
